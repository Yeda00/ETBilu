# Specs — como trabalhamos

A spec guia o trabalho e evolui com ele. Ela não define a implementação de antemão.

1. **Spec principal** da área ([design](design/design.md), [arte](art/art.md)): etapas, marcos, índice das tarefas e registro de decisões.
2. **Sub-spec** para cada tarefa, a partir de [`_template.md`](_template.md).
3. **Executar.** Ao terminar ou mudar de rumo, anotar no **registro** da sub-spec o que mudou e por quê, incluindo os erros.
4. **Atualizar a referência:** o que é mecânica vai para o [GDD](../gdd.md), o que é arte vai para a [bíblia de arte](../art-bible.md).

Status: `todo` · `doing` · `done` · `cut`.

## Regras para agentes (nossos e do Yeda)

- Leia a spec principal e a sub-spec antes de trabalhar na área.
- Atualize o status, o índice e o registro no mesmo commit do trabalho.
- Agente executa, não decide. O que estiver `_TBD_` vira pergunta para o dono.
- Escreva pouco: só o que guia a produção.
